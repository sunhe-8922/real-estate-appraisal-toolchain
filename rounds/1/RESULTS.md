## 不一致根因（93 例全部分类）

| # | 触发模式 | 次数 | Python | JS | 根因 |
|---|---|---|---|---|---|
| 1 | 自引用 `supersedes=自身` | ~56 | C2 | C2+C5+C6 | JS 的 C5（成环遍历所有 dp）与 C6（attempt 自推）**不跳过自引用节点**；Python 的 C2 用 `continue` 跳过该节点全部后续检查。**语义判断：自引用是最根本违规，C2 已定性，C5/C6 冗余（且 C6 自推无意义）→ 对齐 Python** |
| 2 | 被取代者 `attempt=0` | ~18 | C6 | 无 | Python `prev.get("attempt",1)` 取非法值 0 → 期望 1；JS `nextAttempt()` 设计意图「缺失或 <1 视作 1」→ 期望 2。**Python 未实现设计意图 → 对齐 JS** |
| 3 | 被取代者 `attempt=-1` | ~19 | C6 | 无 | 同上（-1 → Python 期望 0） |

> 注：93 例为总计数；前 50 例的聚合分布（c2×30 / attemptneg×10 / attempt0×10）为比例抽样，根因分布由代码路径确定。

## 附带发现

- **生成器缺口**：c4 用例把新节点 `supersedes=链尾`，但链尾自己 `supersedes=前驱`，未形成「两个节点声明同一 supersedes」→ C4 分支零触发，H1-1（Python 双重循环条数差异）未验证。Round 2 修复生成器。
- **已知不对称**：JS 只对 `typeof attempt === "number"` 做 C6；Python 对任意非 None attempt（含字符串 "2"）做比较 → 非法类型输入下会不一致。Round 2 加入字符串 attempt 场景验证。

## 决策

**采纳修复**（Round 2 实施，全部最小变更）：

1. **JS `dp-core.js`**：C5/C6 遍历跳过自引用节点（对齐 Python 语义，C2 已定性）。预期消除 ~56 例。
2. **Python `validate_appraisal_json.py`**：C6 中 attempt < 1 视作 1（对齐 JS `nextAttempt()` 设计意图）。预期消除 ~37 例。
3. **差分生成器**：修复 c4（真双后继）+ 新增 `attempt_str`（字符串 attempt）场景。

风险：极低。变更点均有单测锚定（Node 32 + Python 311），改后全量回归验证。基线快照 `round0-baseline` 可回滚。

## 教训（沉淀）

- **「语义一致」是声明，不是事实**——双端独立实现必须用差分测试机械锚定，注释承诺不可信。
- **分层生成器的价值被验证**：单违规注入让每个不一致都可解释、可归因，无「黑盒不一致」。
- 生成器自身也可能错（c4 场景构造失败）——**度量脚本也要被度量**，通过「每类至少触发一次」的自检断言保证。
