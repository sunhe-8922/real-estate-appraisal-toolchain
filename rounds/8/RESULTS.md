## 〇、一句话结论

**采纳**。核心假设「一致率 100% ≠ 数值正确」成立并被证实：
在**双端实现完全一致、schema 校验全绿**的前提下，注入 `+1 元` 变异在基线

## 一、提案回顾（rounds/8/PROPOSAL.md）

| 项 | 内容 |
|---|---|
| **假设** | 348 个测试全绿 ≠ 数值正确。测试只覆盖「双端一致」+「schema 合法」，从不验证「数值自洽」；R7 的 P1-1（末节点 `ROUND(area×unit)` 与权威总价差 25 元）是人工审查翻出来的，不是 CI 拦下来的。 |
| **改什么** | ① 把 `verify_example_arithmetic.py` 从单示例硬编码脚本泛化为通用协议；② 加 `calculationChain` 公式↔target 一致性断言；③ 接入 pytest 常驻回归。 |
| **为什么** | R7 的整改只改了商业示例的**数值**，没改**协议**——同一形态的错误换个示例还会再犯（本轮已证实）。 |
| **预期收益** | 检出率提升 + 同类缺陷不再依赖人工审查。 |
| **风险** | 新断言可能翻出大量历史缺陷，污染变异判定 → 用「基线自检 + CONTAMINATED 排除」对冲。 |

**度量工具先行**：先建 `tests/mutation_harness.py`（变异测试器）量化基线灵敏度，
再做改造——否则「提升了多少」无从证明。

## 三、实验（严格遵守「一次只变一个变量」）

### B1：仅泛化（不加任何新断言）

改动集中于 `scripts/verify_example_arithmetic.py`：

| 泛化点 | 原（硬编码） | 后（可导） |
|---|---|---|
| 可比实例数 | 写死 3 个 | 按 `len(instances)` 循环，N 实例通用 |
| 市场状况调整 | 写死日期区间 | 从工程 JSON 的 `property.valueDate` 导出，支持 `--value-date` 覆盖 |
| 土地剩余年限 | 写死起算:年限 | 支持 `--land-detail` 传入，缺失降级 INFO |
| 骨架期工程 | 崩溃 | **识别并结构化 SKIP**（`finalTotalValue=0` + 方法全 null） |
| 百分比声明核对 | 写死 9.3% / -14.8% | 按出现顺序匹配声明值集合，取绝对值比对 |

> 过程中修掉一个泛化 bug：analysis 文本写「偏低 14.8%」（无负号）而实算 `-14.8%`，
> 原硬编码版本靠写死符号绕过，泛化后立即暴露 → 改为绝对值比对。

**B1 度量：覆盖率 1/3 → 3/3，检出率**持平 **92.6%**。
**这是预期内结果，不是失败**——泛化改变的是「能测多少」，不是「测得准不准」。

> **字节级证据**：`mutation_result_round8_baseline.json` 与 `_b1.json` 的 sha256
> **完全相同**（`33660177c6c4e3b3…`）——B1 阶段 27 个变异体的判定逐条一致。
> 这证明「泛化未改变检出行为」是可复现的事实，而非口头声称。
> 若两者不同，反而说明泛化过程中悄悄改了断言语义（违反单一变量）。

### B2：新增 `calculationChain` 公式 ↔ target 一致性断言（单一变量）

**关键决策：不重复造轮子。**
排查发现 `scripts/rebuild_excel_formula.py --mode values` 已有现成能力
（`ast` 白名单求值 + `ROUND`/`SUM` 语义 + Excel 四舍五入 + 容差比对）。
B2 直接复用 `rebuild_values()`，而非另写公式解析器。

新增断言：对 `calculationChain` 每个节点，用求值器算出 `formula` 的值，
与 `target` 指向的实际数据比对，超容差即 FAIL。

**B2 立刻抓到 2 处既有缺陷（住宅示例，与 R7 P1-1 同源）**：

| 编号 | 缺陷 | 证据 |
|---|---|---|
| **P1-2A** | chain 节点 `income.value` 公式**引用了数据中不存在的键** `methods.income.netOperatingIncome.growthRate`；公式写的是报酬资本化法（含 growth/holdingPeriod），数据实为直接资本化法 `total=ROUND(48124/0.015)=3208267`。公式与数据**口径不符** | 求值器报「引用了 refs 中不存在的键 = 公式写错」 |
| **P1-2B** | 末节点 `ROUND(area×unit)=3271738` ≠ 权威总价 `3271720`，**差 18 元**；且 `result.totalValue` 与 `result.finalTotalValue` 重复 target | 与 R7 P1-1 完全同形态，**该示例未随 R7 整改同步** |

> **附带发现**：`rebuild_excel_formula.py` 的 `NODE_TOLERANCE=65` 把 18 元的偏差
> **放过了**——容差被调大到刚好容纳错误。这是 P1-1 整改的又一处未收口。
> B2 采用**独立容差**而非复用该常量，避免被同一漏洞掩盖。

**陷阱与对冲**：住宅示例基线已红，会污染变异判定（存活数失真）。
→ 在 harness 中加**基线自检**：变异前先跑一遍，不干净则标记 `CONTAMINATED` 并排除出总分。
本轮正是踩到这个陷阱，机制即时生效。

## 六、沉淀

### 教训（可复用）

1. **一致率 100% ≠ 数值正确。** 双端实现一致只证明「没有分歧」，不证明「算对了」。
   数值类系统必须有独立于实现路径的**第三重校验**（本轮 = 公式求值 ↔ 声明值）。
2. **泛化改变覆盖，断言改变灵敏度。** 两者是不同维度的杠杆，别指望靠重构顺带提升检出率
   （B1 持平是预期内，若据此判「无效」就会误杀正确的中间步骤）。
3. **新断言会翻出历史缺陷——度量工具必须先自检基线干净。**
   否则「存活变异体」里混着真实缺陷，score 失去意义。已固化为 `CONTAMINATED` 判定。
4. **门禁必须做负向验证。** 只看到绿就收工，可能拿到的是一个从不触发的空门禁。
   +1 元变异是最便宜的验证成本。
5. **提容差是最隐蔽的技术债。** `NODE_TOLERANCE=65` 恰好容纳 18 元错误——
   容差调整必须有缺陷编号背书，否则等于把 bug 合法化。
