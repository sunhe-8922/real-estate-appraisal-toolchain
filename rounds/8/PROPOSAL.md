## 一、为什么换维度（递归规则：连续 3 轮同维度需切换）

| 轮 | 优化维度 | 产出 |
|---|---|---|
| R5 | 评估体系·覆盖率扩展（决策链函数） | 函数侧 1000/1000 |
| R6 | 评估体系·覆盖率扩展（畸形输入/指纹） | 4 漂移全消 |
| R7 | 评估体系·覆盖率扩展（oracle 交叉/动作差分） | 0 分歧 |

R5-R7 连续 3 轮都在「**扩大差分覆盖面**」这一条轴上推进，一致率已连续 3 轮锁死 100%，
边际产出从「抓到 P0 语义 bug」退化为「覆盖率数字增长」。而 R7 审查却在第 4 个维度
（**数值正确性**）一次性抓到 P1-1/P2-1/P2-2/P2-3 四项——且全部落在现有评估协议的盲区里。

**结论**：一致率已饱和，本轮切换到「数值自洽性」维度，并把重点从"再多测一点"
改为"**现有协议到底能抓到多少缺陷**"（协议有效性度量）。

基线暴露三件事（均为机械实测，非推断）：

1. **泛化能力 = 0**：`verify_example_arithmetic.py` 只支持 adjustments 的
   **`*Details` 子项形态**；schema v1.5 明确允许**标量形态**（`location/physical/interest`
   为合并后倍率，见 schema 第 260-306 行），格力海岸工程 JSON 用的正是标量形态 → 直接崩。
2. **可选字段无容错**：`res["crossMethodDifference"]` 无条件访问，但 schema 中它是
   optional（`result.required` 仅 5 项）。
3. **泛化与灵敏度的真实张力**：脚本里 6 处硬编码常量
   （`eff_age == 11`、`+remainingUsefulLife == 58.5`、`9.3%`、`-14.8%`、`range(3)`、
   `2026 - completionYear`）一旦泛化，最省事的做法就是删断言或放宽容差——
   **那会让校验器变"永远绿"**。这是本轮唯一实质性风险。

## 三、假设（1 个，配套 1 个度量手段）

### H8-1（主假设，评估体系维度）

> **数值自洽性能否从「人工审查发现」转为「机器门禁拦截」，且不因泛化而牺牲灵敏度。**

- **改什么**：
  1. 校验器**泛化**：双形态 adjustments（标量 / `*Details` 子项，两者并存时以
     子项为准反算标量并交叉验证）、optional 字段容错、价值时点与竣工年**可导**
     （不再硬编码 2026 / 11 / 58.5）、权重从 chain 解析失败时按 **N 实例**回退
     而非固定 `range(3)`、方法间差异率**实算**而非硬编码 9.3%/−14.8%。
  2. **常驻回归**：新建 `tests/test_example_arithmetic.py`，自动遍历
     `schema/example-*.json` + `outputs/*.json` 中所有符合工程形态的 JSON，
     逐文件跑校验器并断言 0 FAIL。
  3. **变异测试器**（度量手段，非被测对象）：新建 `tests/mutation_harness.py`，
     对示例 JSON 注入一组**已知缺陷**（含 P1-1 原始形态），统计「注入后被校验器抓到」
     的比例 = **变异检出率（mutation score）**。
- **为什么**：R7 的 P1-1 证明"双端一致 + schema 合法"完全不能推出"数值自洽"；
  而数值错误在估价业务里是**最高代价**的一类（公式算不出结论值）。
- **预期收益**：
  - 工程 JSON 校验覆盖率 `1/3 → 3/3`（含格力海岸真实工程）；
  - 数值类缺陷进入 CI 门禁，不再依赖人肉审查；
  - mutation score 首次可量化，为后续每轮提供可比对的灵敏度基线。
- **风险与对冲**：泛化最易导致断言放宽（风险 3 所述）。**对冲设计**：
  泛化与变异测试**同批交付**，且变异集必须包含 P1-1 原始形态作为回归锚点——
  若泛化后 mutation score 下降，判定回退并回滚。

### H8-2（备，本轮不做）

变异语料扩展到红线检查 / 决策点数值。按"一次只变一个变量"原则留待 R9。

## 四、实验设计（一次只变一个变量）

单变量 = **校验器的泛化实现**。顺序固定，每步留档：

| 步 | 动作 | 度量 |
|---|---|---|
| A | 建变异测试器（度量工具），在**现有校验器**上跑基线 mutation score | 基线灵敏度（示例 2 个） |
| B | 泛化校验器（唯一变量变更） | 覆盖率 1/3 → 3/3；重跑变异器 |
| C | 常驻回归 `tests/test_example_arithmetic.py` | Python 全量通过数变化 |

**判定规则**：
- mutation score **不下降** 且 覆盖率 **上升** → 提升，采纳固化；
- mutation score 下降 → 回退，根因分析（是断言被放宽还是变异集不匹配）；
- 覆盖率未上升 → 持平，保留日志。
