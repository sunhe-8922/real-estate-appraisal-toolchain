# 人工决策点架构设计

> **创建时间**：2026-08-18
> **状态**：Schema v1.3 实施中
> **设计依据**：sun 的 9 维偏好矩阵（Agent / 高可控 / 专业节点介入 / 连续执行 / 证据+理由+风险 / 结论优先 / 风险分级 / 目标驱动 / 能力扩张）
> **修订**：v2 — 增加"可比实例选取"等方法特定决策点，新增"与估价对象差异"字段

---

## 一、设计哲学

| 偏好维度 | 架构落地方案 |
|----------|------------|
| Agent（AI 是执行主体） | AI 自主完成资料搜集、测算、报告生成全流程 |
| 高可控（不追求盲目自治） | 固定 + 条件决策点，AI 在 DP 必须暂停等待人类判断 |
| 专业节点介入（人不是操作员） | DP 呈现"决策包"——结论+证据+理由+风险+对比，人基于材料判断 |
| 节点之间连续执行 | 两个 DP 之间 AI 不被打断，自主完成所有中间步骤 |
| 证据+理由+风险 | 决策包五段式结构，每段有明确内容要求 |
| 结论优先 | 决策包第一段就是 AI 的推荐结论，不是信息堆砌 |
| 风险分级 | 每个风险标注 P0/P1/P2，按错误代价排序 |
| 目标驱动 | 用户描述"帮我做一份抵押估价报告"，不描述步骤 |
| 能力扩张 | AI 处理繁琐计算和格式化，人专注专业判断和风险把控 |

**核心原则**：决策点放在"错误代价高且需要专业判断"的位置，不是放在每个步骤。两个决策点之间，AI 全速执行。

## 二、决策点体系

### 2.1 固定决策点（每次估价都触发）

#### DP1: 估价事项确认 — P0

**位置**：用户目标输入后，资料搜集前
**为什么暂停**：估价目的、价值时点、估价对象、价值类型——四要素任何一个错误，整份报告作废。

| 决策包字段 | 内容示例 |
|-----------|---------|
| 结论 | 估价目的：抵押估价；价值时点：2026-08-18；估价对象：武汉市洪山区 XX 住宅；价值类型：市场价值 |
| 证据 | 委托合同关键条款、不动产权证摘要 |
| 理由 | 抵押估价要求市场价值（3.0.3条）；需同时采用两种以上方法 |
| 风险 | P0：估价对象含附属面积，需确认是否计入建筑面积 |
| 与估价对象差异 | —（本 DP 不涉及对比） |

**人类决策**：批准 / 调整四要素 / 驳回重述

#### DP2: 测算方案确认 — P1

**位置**：资料搜集完成后，四大方法测算前
**为什么暂停**：方法选择和数据充分性评估需要专业判断。选错方法或数据不足，后续测算全部白费。

| 决策包字段 | 内容示例 |
|-----------|---------|
| 结论 | 建议选用比较法（权重 0.6）+ 收益法（权重 0.4） |
| 证据 | n 个候选交易实例（成交 6 个月内，T0-T1 信源）；区域租金数据完整（5 年历史）；不适用假设开发法 |
| 理由 | 交易活跃区域比较法为首选（4.1.2 条第 1 款）；有稳定租金收益可交叉验证 |
| 风险 | P1：可比实例 B 距地铁站远 800m，区位修正可能接近 20% 上限 |
| 与估价对象差异 | —（本 DP 在方法层面，不涉及实例对比） |

**人类决策**：批准方案 / 调整方法或权重 / 驳回要求补充资料

#### DP3: 测算结果审核 — P1

**位置**：四大方法全部测算完成后，报告生成前
**为什么暂停**：最后一次在报告生成前审核。红线校验、跨方法一致性、结果合理性——都需要估价师确认。

| 决策包字段 | 内容示例 |
|-----------|---------|
| 结论 | 比较法 25,773 元/m²，收益法 24,850 元/m²，红线 5/5 全通过，建议加权 25,404 元/m² |
| 证据 | 红线校验表、修正系数明细、跨方法一致性检查 |
| 理由 | 两种方法差异 3.7%（<10% 可接受），比较法数据更充分权重 0.6 |
| 风险 | P1：可比实例 B 区位修正 18.5%，接近 20% 上限 |
| 与估价对象差异 | —（本 DP 在结果层面，不涉及实例对比） |

**人类决策**：批准结果 / 调整参数（换可比实例/调权重/调修正系数）/ 驳回重算

#### DP4: 报告签发 — P0

**位置**：报告生成完成后
**为什么暂停**：报告一旦签发即具有法律效力。

| 决策包字段 | 内容示例 |
|-----------|---------|
| 结论 | 报告完整，建议签发。最终估价结果：总价 327 万元，单价 25,404 元/m² |
| 证据 | 报告 18/18 项合规检查全通过；假设限制条件已声明；calculationChain 8/8 一致 |
| 理由 | 报告结构符合第 7 章要求；测算结果经 DP3 审核确认 |
| 风险 | P0：报告使用期限 ≤1 年需在报告中声明 |
| 与估价对象差异 | — |

**人类决策**：签发 / 要求修订

### 2.2 条件决策点（方法特定，按需触发）

条件决策点只在对应方法被使用时触发。不使用的方法不产生决策点，不会增加打断次数。

#### DP-comp: 可比实例选取 — P1

**触发条件**：比较法 `applicable=true`
**位置**：比较法 Step 2（选取可比实例）完成后，Step 3（建立比较基础）前
**为什么暂停**：可比实例选错，后面所有修正都是错的。AI 可以自动筛选，但最终选哪几个需要估价师确认。

| 决策包字段 | 内容示例 |
|-----------|---------|
| 结论 | 推荐选取实例 A / B / C（3 个） |
| 证据 | 实例 A：XX 小区 3-2-501，成交 2026-06-15，25,000 元/m²（链家成交记录，T0）；实例 B：XX 小区 5-1-803，成交 2026-07-01，25,500 元/m²（贝壳成交记录，T1）；实例 C：XX 小区 2-3-402，成交 2026-05-20，24,800 元/m²（中介实测，T2） |
| 理由 | 三个实例均在 6 个月内成交，与估价对象同小区，区位差异最小 |
| 风险 | P1：实例 B 距地铁站远 800m，区位修正预计 18%；P2：实例 C 为 T2 信源，需交叉验证 |
| 与估价对象差异 | A：同栋同户型，楼层差 2 层；B：同小区不同栋，面积差 5m²，地铁距离差 800m；C：同小区，装修标准差一档 |

**人类决策**：接受 A/B/C / 修改（替换某实例） / 否决（要求重新筛选）

#### DP-income: 报酬率确定 — P1（可选）

**触发条件**：收益法 `applicable=true`
**位置**：收益法报酬率确定后，价值测算前
**为什么暂停**：报酬率是收益法最敏感的参数，±0.5% 对结果影响可达 10%+。确定方法（市场提取/累加/投资收益率排序）需要专业判断。

#### DP-cost: 重置成本确定 — P1（可选）

**触发条件**：成本法 `applicable=true`
**位置**：成本法重置成本确定后，折旧测算前

#### DP-hypoth: 开发完成后价值确定 — P1（可选）

**触发条件**：假设开发法 `applicable=true`
**位置**：假设开发法开发完成后价值确定后，后续支出测算前
**为什么暂停**：4.5.7 条红线——开发完成后价值不得用成本法测算。确定方式需要专业判断。

### 2.3 典型估价的决策点序列

以"比较法 + 收益法"抵押估价为例（最常见场景）：

```
用户输入
  → DP1 估价事项确认 [P0 固定]
  → 资料搜集 + 方法预判
  → DP2 测算方案确认 [P1 固定]
  → 比较法测算
    → DP-comp 可比实例选取 [P1 条件]
    → 修正计算 + 红线校验
  → 收益法测算
    → DP-income 报酬率确定 [P1 条件，可选]
    → 收益计算 + 红线校验
  → DP3 测算结果审核 [P1 固定]
  → 报告生成 + 结果确定
  → DP4 报告签发 [P0 固定]
  → 交付
```

共 5-6 个决策点（4 固定 + 1-2 条件），其中条件决策点只在对应方法中使用时触发。

| evidence | array | 是 | 证据列表，每项含 item + source |
| reasoning | string | 是 | 推荐理由 |
| risks | array | 是 | 风险列表，每项含 description + level + mitigation |
| comparison | array | 否 | 与估价对象差异（方法特定 DP 使用），每项含 instance + differences |

| humanDecision.action | enum | 是 | approved / modified / rejected |
| humanDecision.modifications | string | 否 | 调整内容（action=modified 时必填） |
| humanDecision.comment | string | 否 | 决策备注 |

## 四、与现有架构的集成

### 不改动的部分

- 7 个技能保持不变
- Schema v1.2 核心字段不变，`decisionPoints` 作为可选字段新增
- calculationChain、红线校验、Excel 同步链路不变

### 新增的部分

1. **Schema v1.3**：新增 `decisionPoints` 可选字段 + `$defs.decisionPoint` / `$defs.riskItem` / `$defs.evidenceItem` / `$defs.comparisonItem`
2. **编排层**：AI 在执行工作流时，自动在决策点暂停，生成决策包，等待人类响应后继续
3. **决策历史**：所有决策记录写入 JSON 的 `decisionPoints[]`，随工程文件保存

## 六、设计权衡

| 决策 | 选择 | 理由 |
|------|------|------|
| 决策点类型：纯固定 vs 固定+条件 | 固定+条件 | 方法特定判断（如可比实例选取）需要独立 DP；不使用的方法不触发，不增加噪音 |
| 决策点位置：技能内 vs 编排层 | 编排层 | 技能保持不变，编排层统一管理暂停-恢复 |
| decisionPoints 存储位置 | JSON 内 | 随工程文件保存，不增加文件管理负担；可选字段不破坏兼容 |
| comparison 字段 | 可选 | 固定 DP 不需要对比，方法特定 DP（如 DP-comp）需要 |
| 驳回后的行为 | 视情况 | DP1 驳回→重述事项；DP-comp 驳回→重新筛选；DP3 驳回→局部重算 |
