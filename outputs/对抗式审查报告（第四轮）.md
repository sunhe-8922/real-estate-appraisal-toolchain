## 二、发现的问题

### P1-1 前端 example-data.js 未同步 v1.5（一致性缺陷）

- **现象**：`app/js/example-data.js` 内嵌示例数据 `schemaVersion="1.4"`、22 条 evidence 均无 `sourceGrade`，而主示例数据已升级 v1.5。
- **影响**：用户在前端"载入示例"看到的是旧版数据，与 schema v1.5 脱节；基于它操作导出的 JSON 与项目当前版本不一致。
- **根因**：v1.5 升级时只改了 `schema/example-武汉洪山住宅.json`，未同步前端手工提取的内嵌副本。
- **修复**：从 v1.5 示例数据重新同步 decisionPoints（22/22 含 sourceGrade）+ schemaVersion=1.5。
- **验证**：浏览器载入示例 → schemaVersion=1.5、evidence.sourceGrade=T1、徽章渲染成功。

### P1-2 条件 DP fixture 触发方法为 null（业务语义缺陷）

- **现象**：`orchestrator_pending_cost.json` / `orchestrator_pending_hypoth.json` 中 `methods.cost` / `methods.hypotheticalDev` 均为 `null`，但 `decisionPoints` 含 DP-cost / DP-hypoth（`trigger=method:cost/hypotheticalDev`）。
- **影响**：① 违反决策点规格——DP-cost/DP-hypoth 触发条件要求 `methods.xxx.applicable=true`，null 表示"未采用该方法"，DP 不应出现；② 决策包结论声称的数值（成本法 6,850/5,822.5 元/m²、假设开发法 12,500/8,900 元/m²）在结构化数据中**无法溯源**，违反编排 skill 铁律 4（证据溯源红线）。
- **根因**：构造 fixture 时直接复制示例数据（示例数据的 cost/hypoth 为 null 属正常——示例数据未采用这两种方法），未按 DP 触发语义补齐方法数据。
- **修复**：填充合法 methods 对象（applicable=true + pathType/analysisMethod/reproductionCost/developmentValue/finalValue/weight/redLineChecks 红线条目），决策包结论数值与结构数据对齐。
- **验证**：Python 校验通过；浏览器加载 cost fixture → DP-cost 渲染正常、结论含 6,850 可溯源；**新增溯源测试锁定**（`test_fixtures.py`：触发方法必须存在且 applicable=true + finalValue.unit 可溯源）。

### P2-1 前端未呈现 sourceGrade 结构化字段（UI 不完整）

- **现象**：`evHtml()` 只显示 evidence 的 item + source 文本，不展示结构化 `sourceGrade`。
- **影响**：信源等级虽在 source 文本中有 `(T0)` 标记可读，但结构化字段（v1.5 的校验依据）不直观。
- **修复**：`evHtml()` 增加 `src-grade` 徽章（T0 绿 / T1 蓝 / T2 灰），浏览器验证渲染成功。

### P2-2 HANDOFF §五 验证命令过时（文档一致性）

- **现象**：HANDOFF 验证命令仍为"v1.4 schema 测试""根 schema == v1.4 副本""Python 全量 273"。
- **修复**：更新为 v1.5 专项 + 4 fixture 验证 + 根 schema == v1.5 副本 + 308 基线 + 前端 server 目录修正。

## 五、审查结论

1. **schema 层**（v1.5/sourceGrade/迁移）经攻击验证**无缺陷**：diff 纯净、解析一致、幂等正确。
2. **本轮产物真实缺陷集中在"数据与业务语义脱节"**：前端示例副本未同步（P1-1）、条件 DP fixture 触发方法缺失（P1-2）——两者都是"示例/演示数据与 schema 演进未联动"的典型问题，与第三轮"前端 JSON 与 schema 约束脱节"同根。
3. **修复均以测试锁定**：溯源测试（4 用例）保证 P1-2 不再复发；schema diff 校验可加自动化（见下）。
4. **遗留**：
   - schema diff 纯净性检查是手工脚本，可沉淀为 `tests/test_schema_v15.py` 的 `test_root_schema_equals_v15_copy`（已存在，等价覆盖）。
   - 前端 example-data.js 的同步机制仍是手工的——建议下轮在 CHANGELOG/发布清单中明确"升级 schema 时须同步 example-data.js"。
