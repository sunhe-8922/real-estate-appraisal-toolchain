## 二、P0 详述：eval 沙箱逃逸（已修复）

### 漏洞

`scripts/rebuild_excel_formula.py` 第 168 行（修复前）：

```python
ns = {"round": round, "sum": sum, "SUM": sum, "__builtins__": {}}
return eval(body, ns)  # noqa: S307 — 公式为本工具生成，非外部输入
```

注释声称"公式为本工具生成，非外部输入"——**这个威胁模型判断是错的**：
- `--chain` 参数明确接受任意外部 JSON 文件；
- 本项目核心场景恰恰是 AI 生成 / 交换 calculationChain，输入不可信是常态。

### 实测逃逸（修复前）

空 `__builtins__` 沙箱的经典绕过——经 `object` 子类遍历拿到 `os._wrap_close`，取其 `__globals__['system']`：

```
payload: [c for c in ().__class__.__bases__[0].__subclasses__()
          if c.__name__ == '_wrap_close'][0].__init__.__globals__['system'](...)
结果:   命令实际执行，marker 文件生成 → 沙箱逃逸成立
```

存在**两条独立注入向量**，均已实测：
1. **恶意 formula**：calculationChain.nodes[].formula 直接携带逃逸代码；
2. **数据值注入**：refs 指向数据中的字符串字段，字段值被 `str(val)` 原样拼进 eval 表达式执行。

### 修复（AST 白名单求值器）

新增 `safe_eval()`：解析为 AST 后仅放行数字/列表字面量、`+ - * / **`、一元 `+ -`、以及 `round/sum/SUM` 三个白名单函数调用；其余节点类型（属性访问、下标、推导式、布尔运算、名称引用、lambda 等）一律抛 ValueError。

修复后双向验证：
- **逃逸复测**：两条注入向量均被拒绝（"仅允许调用 round/sum" / "非法语法节点: BoolOp"），marker 不再生成；
- **回归**：合法 calculationChain 仍 7/8 PASS（`income.value` SKIP 为已知数据口径问题）。

### 固化

`tests/test_adversarial_v12.py` 13 个用例：8 个恶意结构参数化拒绝、合法公式放行基线、两条端到端无副作用测试（marker 文件不存在断言）、2 个 migrate 写回测试。**防止将来有人把 safe_eval 改回裸 eval。**

## 三、P1/P2 详述

### #3 factor 负数（已修复）

`$defs.factorDetail.factor` 原仅 `type: number`，实测 `-9999` 通过。偏差加总合并 `100/(100+Σ(f-100))` 在非正指数下分母可≤0，结果无意义。已加 `exclusiveMinimum: 0`（root + v1.2 快照同步，一致性已验证）。

### #4 migrate 数据丢失（已修复）

`result: null` 时 `_migrate_1_0_to_1_1` 把推断的 calculationMode 写进了临时字典未写回，notes 声称已推断但数据实际丢失。已修复为写回，3 种输入（null/缺失/正常 dict）均验证。

### #5 redLineChecks 弱约束（未改，设计权衡）

实测 `rule` 可填任意文本、`passed` 可全 false 仍通过 schema。这是**有意为之**：红线判定依赖线下专业核验，schema 只保证"有检查记录"这一结构，不代行业务判断。validate_degraded 已强制"至少一个方法红线非空"。若要更强约束，应做成 enum(rule) + passed=false 必填 detail，需 sun 决策是否收紧。

### #6 income.value SKIP（已知，非缺陷）

示例采用 directCapitalization 模式无 growthRate，该节点公式适用于 fullRemainingLife/holdAndResale。数据口径问题，HANDOFF 已记录。
