## 二、发现清单

### P1-1 v9.0 宪章引用 3 个不存在的文件——宪章自身不可执行

**证据**：新版 `CLAUDE.md`（v9.0）两处硬依赖：

- **Intent 协议**："每个项目**必须**包含 `intent.md`，它是项目目标的事实来源"；
- **上下文协议加载顺序**："CLAUDE.md → intent.md → architecture.md → decisions.md → …"。

实测：`intent.md`、`architecture.md`、`decisions.md`、`.context/` 均**不存在**（`ls` 全部 No such file）。

**影响**：任何按该宪章执行的会话，在"上下文加载"第二步就会卡住或被迫违规；宪章的权威性自第一行起就不成立。这是治理文档的空头支票——写了义务，没有基础设施。

**修复选项**（需 sun 决策，见 §四）：

- A：补齐三文件（可从 HANDOFF-08-19 + README 提取，成本低）；
- B：把"必须"降级为"建议，缺失时用 HANDOFF/README 兜底"；
- C：不引入 v9.0（回退旧版）。

### P1-2 v9.0 宪章未提交，已提交的旧版被静默替换

**证据**：`git diff CLAUDE.md` —— 49 行《高可靠性编码行为准则》被整体替换为 182 行 v9.0；`git status` 显示该修改**未提交**。远程 `origin/master` 上的 `CLAUDE.md` 仍是旧版。

**影响**：

1. **版本漂移**：不同会话/机器读到不同宪章——本地新会话读 v9.0（且因引用缺失而卡壳），远程克隆者读到旧版；
2. 旧版准则（含"GitHub 成熟开源方案直接复用，只写必要 glue code"这条 sun 的明确规则）在 v9.0 中只以笼统的"复用优先"存在，**具体表述被稀释**，若直接提交覆盖将丢失该约束的显性表述。

**修复**：与 P1-1 决策联动。提交前先解决引用缺失；建议提交信息中保留旧版"开源复用"条款的显性表述（并入核心原则第 8 条）。

### P1-3 `outputs/CLAUDE.md` 双副本——违反单一事实源

**证据**：`outputs/` 下出现未跟踪的 `CLAUDE.md`，与根部 `CLAUDE.md` 内容哈希一致（去 `\r` 后 md5 同为 `844a327a…`，仅行尾符不同）。

**影响**：

1. **位置错误**：`outputs/` 是交付产物区（报告/模板/交接文档），项目治理文件放进来，后续会误导阅读者以为它是某次任务的"交付物"；
2. **双副本必然漂移**：本轮内容相同只是运气好（同时生成），任何一方单独修改都不会同步另一方——这正是本项目在 v1.5 升级中刚用 `test_example_data_sync.py` 机制化治理过的同类问题（schema 根/副本脱节），现在治理文件自己犯了同样的错。

**修复**：删除 `outputs/CLAUDE.md`，宪章只留根部一份。

### P2-1 templates xlsx 抖动第四次复现——根治继续欠账

**证据**：`git status` 显示 4 个 `outputs/templates/*_模板.xlsx` 再次出现未提交修改（测试运行时 conftest 重新生成，元数据变化）。

**影响**：HANDOFF-08-19 §2.6 已明确预警，本轮证实预警成立。每次全量测试后工作区变脏，持续制造"误提交噪音"与"审查误报"两类风险。

**修复**（沿用 §四 迭代建议 #4）：① conftest 生成时固定元数据（写入时间戳/作者字段为常量）；或 ② 模板产物移出版本控制 + 保留生成脚本。二选一即可，工作量均很小。

### P2-2 本地远程跟踪分支曾丢失（已诊断并修复，留档防误判）

**证据**：审查开始时 `git status -sb` 显示 `## master...origin/master [gone]`；`.git/refs/remotes/origin` 整个目录不存在、`packed-refs` 无 origin 条目。

**诊断**：本地远程跟踪引用被清空（可能是清理操作或环境迁移所致），**不是仓库损坏、也不是远程丢失**——`git ls-remote` 证明 GitHub 上 `master = 2a95a85` 完好。

**修复**：已执行 `git fetch origin`（只读）恢复 `origin/master` 跟踪，现 `git status -sb` 正常。留档意义：下次见到 `[gone]` 先 `ls-remote` 核实远程，勿误判为推送丢失。
