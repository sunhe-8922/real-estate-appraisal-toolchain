### 1.2 Schema 版本化（v1.0 固化 + v1.1 扩展 + 迁移机制）

**目标**：引入版本化机制，使 schema 可演进而不破坏历史数据。

#### 新增文件

| 文件                                         | 说明                                                       |
| ------------------------------------------ | -------------------------------------------------------- |
| `schema/v1.0/appraisal-result.schema.json` | v1.0 历史快照，`schemaVersion: const "1.0"`，`$id` 指向 v1.0，不可变 |
| `schema/v1.1/appraisal-result.schema.json` | v1.1 当前版本，`schemaVersion: pattern "^1\\.1$"`，3 个可选新字段    |
| `scripts/migrate_schema.py`                | 版本迁移脚本，支持 1.0→1.1 自动补全 + 同版本 skip + 预览模式                 |
| `CHANGELOG.md`                             | 版本变更日志，遵循 Semantic Versioning                            |
| `tests/test_schema_migration.py`           | 29 个版本化迁移测试（6 个测试类）                                      |

#### v1.1 新增字段（全部 optional，向后兼容）

| 字段路径                      | 类型                                                                                        | 说明                       |
| ------------------------- | ----------------------------------------------------------------------------------------- | ------------------------ |
| `valuation.estimatedDate` | `string` (date format)                                                                    | 预计成交日期，适用于抵押估价等预测场景      |
| `result.calculationMode`  | `enum`: `weightedAverage` / `arithmeticMean` / `primaryMethodDominant` / `expertJudgment` | 结果确定方式                   |
| `crossMethodNotes`        | `string`                                                                                  | 跨方法综合讨论笔记，对应报告第 7.0.15 节 |

#### 验证器更新（`scripts/validate_appraisal_json.py`）

- 新增 `detect_version(data)` 函数：读取 `data["schemaVersion"]` 返回版本号或 `"unknown"`
- `validate_full(data, version=None)` 新增 `version` 参数：
  - `version=None`（默认）：自动检测 `data["schemaVersion"]` 路由到对应版本 schema
  - `version="1.0"` / `"1.1"`：强制指定版本
  - 未知版本：回退到根目录 `schema/appraisal-result.schema.json`（向后兼容老脚本）
- `_load_schema(version)` 支持 `v1.0` / `v1.1` / `None`（默认）三种路径

#### 迁移脚本设计（`scripts/migrate_schema.py`）

```bash
# 迁移数据文件
python scripts/migrate_schema.py --input old.json --output new.json

# 仅预览变更（不写文件）
python scripts/migrate_schema.py --input old.json --preview

# 查看支持的迁移路径
python scripts/migrate_schema.py --list
```

迁移逻辑：

1. `schemaVersion`: `"1.0"` → `"1.1"`
2. `result.calculationMode`: 根据 `determinationMethod` 文本自动推断（含"加权平均"→`weightedAverage`，含"算术平均"→`arithmeticMean`，含"为主"→`primaryMethodDominant`，否则→`expertJudgment`）
3. `valuation.estimatedDate` / `crossMethodNotes`: 不自动填充（用户按需填写）
4. 同版本调用（1.1→1.1）直接返回原数据，无副作用

#### 关键设计决策

| 决策                 | 选择                                           | 理由                                |
| ------------------ | -------------------------------------------- | --------------------------------- |
| v1.0 位置            | `schema/v1.0/` 独立目录 + 版本化 `$id`              | 历史版本不可改，保持原始不变                    |
| v1.0 schemaVersion | `const: "1.0"`（锁死）                           | v1.0 数据永远能追溯到原始 schema            |
| v1.1 schemaVersion | `pattern: "^1\\.1$"`                         | 从 const 升级为 semver pattern，支持未来版本 |
| 新增字段 optional      | 全部不加入 `required`                             | 向后兼容，v1.0 数据迁移后即可用 v1.1 验证        |
| 默认 schema 位置       | `schema/appraisal-result.schema.json` 仍指向最新  | 老脚本不动，向后兼容                        |
| 版本检测策略             | `detect_version` 优先读 `data["schemaVersion"]` | 自动路由，用户无需手动指定                     |
