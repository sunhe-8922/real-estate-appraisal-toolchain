### 1.1 决策点规格定义（Phase 2 已固化，见 `outputs/决策点规格定义.md`）

8 个 DP 完整规格（DP1-DP4 固定 + DP-comp/DP-income/DP-cost/DP-hypoth 条件），每个含六要素：标识 / 触发条件 / 暂停位置 / 输入条件 / 内容模板 / 输出动作。

决策包五段式模板：结论先行 → 证据（含 sourceGrade 溯源红线 T0/T1/T2）→ 理由 → 风险（P0/P1/P2 + mitigation）→ 与估价对象差异（方法特定 DP）。

人类决策动作语义：
- `approved`：批准，按当前决策包继续
- `modified`：局部修正，`modifications` 必填，**不产生新 DP**
- `rejected`：整体否决，**创建新 DP**（见 1.2 决策链模型）

### 1.2 决策链模型（Phase 2 已建模，Phase 3 已接入前端）

核心决策：`status=rejected` 后**创建新 DP**，旧 DP 保留为**不可变审计记录**。

| 模型要素 | 规则 |
|---------|------|
| 状态机 | `pending` → `approved`/`modified`（终结态）；`pending` → `rejected`（非终结 → 触发新 DP） |
| 建链 | 新 DP 通过 `supersedes` 指向旧 DP；`attempt` 记录尝试序号（1 起，后继 = 前驱 + 1） |
| 审计 | 旧 DP 不删除、不修改，保留否决原因作为过程证据 |
| 学习 | 驳回理由（`humanDecision.comment`）是 AI 学习信号 |

Schema v1.4 建模：`decisionPoint` 新增可选 `supersedes` / `attempt`（向后兼容 v1.3）。业务校验 C1-C6 由 `scripts/validate_appraisal_json.py` `_check_decision_chain()` 强制。
