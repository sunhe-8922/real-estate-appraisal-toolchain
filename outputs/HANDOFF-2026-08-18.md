### 1.1 决策点规格定义文档（提交 `fd7e07d`，新增 `outputs/决策点规格定义.md`）

**8 个 DP 完整规格**，每个含六要素（标识 / 触发条件 / 暂停位置 / 输入条件 / 内容模板 / 输出动作）：

| DP | 名称 | 类型 | 风险级 | 触发 | 暂停位置 |
|----|------|------|:--:|------|------|
| DP1 | 估价事项确认 | 固定 | P0 | always | 项目启动后，资料搜集前 |
| DP2 | 测算方案确认 | 固定 | P1 | always | 资料搜集+方法预判后，测算前 |
| DP3 | 测算结果审核 | 固定 | P1 | always | 各方法测算完成后，报告生成前 |
| DP4 | 报告签发 | 固定 | P0 | always | 报告生成后，交付前 |

| DP-cost | 重置成本确定 | 条件 | P1 | method:cost | 重置成本确定后，折旧测算前 |
| DP-hypoth | 开发完成后价值确定 | 条件 | P1 | method:hypotheticalDev | 开发完成后价值确定后，后续支出测算前 |

**决策包五段式模板**（结论先行）：结论 → 证据（含 sourceGrade 溯源红线：T0 官方一手 / T1 平台机构 / T2 口头间接）→ 理由 → 风险（P0/P1/P2 分级 + mitigation）→ 与估价对象差异（方法特定 DP）。

**人类决策动作语义**：
- `approved`：批准，按当前决策包继续
- `modified`：局部修正，`modifications` 必填，**不产生新 DP**
- `rejected`：整体否决，**创建新 DP**（见 1.2 决策链模型）

### 1.2 决策链模型（P2-2 决策：驳回后行为，已固化到设计文档 + Schema v1.4 建模）

**核心决策**：`status=rejected` 后**创建新 DP**，而非修改旧 DP；旧 DP 保留为**不可变审计记录**。

| 模型要素 | 规则 |
|---------|------|
| 状态机 | `pending` → `approved`/`modified`（终结态）；`pending` → `rejected`（非终结 → 触发新 DP） |
| 建链 | 新 DP 通过 `supersedes` 字段指向被取代的旧 DP；`attempt` 记录尝试序号（1 起，后继 = 前驱 + 1） |
| 审计 | 旧 DP（rejected）不删除、不修改，保留否决原因作为过程证据 |
| 学习 | 驳回理由（humanDecision.comment）是 AI 的学习信号，后续决策需规避同类问题 |

**理由**：审计合规（GB/T 50291-2015 要求过程可追溯，否决证据不可销毁）、决策链可回溯（一次估价的完整决策轨迹）、AI 学习信号。

**Schema v1.4 建模**：`decisionPoint` 新增两个**可选**字段（向后兼容 v1.3）：
- `supersedes` (string)：被本 DP 取代的前一个 DP id
- `attempt` (integer, min 1)：决策链内尝试序号

**业务校验 C1-C6**（`scripts/validate_appraisal_json.py` 新增 `_check_decision_chain()`，JSON Schema 无法表达数组级约束）：

| 编号 | 约束 | 违反示例 |
|------|------|---------|
| C1 | supersedes 存在性 | 引用不存在的 DP id |
| C2 | 不自引用 | supersedes 指向自身 |
| C3 | 被取代者必须 rejected | 前驱 status=approved |
| C4 | 1:1 后继（防分叉） | 同一 DP 被两个后继取代 |
| C5 | 不得成环 | A→B→A 双向环 / 三节点环 |
| C6 | attempt 一致性 | 后继 attempt ≠ 前驱 attempt+1 |
