## 二、P1 — 应当修复

### P1-1：calculationChain 末节点公式与 finalValue 不自洽（25 元）；收益/成本法 total×unit 不闭合（同源）

`calculationChain` 末节点 `result.totalValue`：

```json
{ "id": "result.totalValue",
  "target": "result.finalTotalValue",
  "formula": "ROUND({{area}}*{{unitValue}},0)",
  "refs": { "unitValue": "result.finalUnitValue" } }
```

实算：`ROUND(85×32991)=2804235`，而 `target` 指向的 `result.finalTotalValue=2804260`——**公式算不出目标值**。
同源问题蔓延到收益/成本法：`finalValue.total` 由除法取整得到，`finalValue.unit` 由 total÷85 取整反推，
两者乘积必然回不到 total（收益差 24、成本差 11）。

**根因**：总价是"先取整的加权值"（ROUND(2804257,−1)），单价是"总价÷85 再取整"（32991），
回乘即断裂。这正是项目硬纪律"总价三级验算：单价×面积=ROUND(M×N)=合计行"要防的形态。

**修复建议**：
1. 统一取整顺序：以 `total` 为唯一事实源，`unit` 节点公式改为 `=ROUND({{total}}/{{area}},0)` 并在 refs 里挂 total，
   删除/改写 `result.totalValue` 节点（或改为 `total = ROUND(area×unit)` 但需同步改 unit 使回乘成立——二选一，不许两值并列矛盾）；
2. 收益/成本法 finalValue 补 unit 推导节点（`=ROUND(total/area,0)`），消除"两值并列但不闭合"；
3. 修复后重跑示例校验 + 总价三级验算断言（应新增一条自动化断言：`total == round(unit*area)` 或声明取整差并入库）。
