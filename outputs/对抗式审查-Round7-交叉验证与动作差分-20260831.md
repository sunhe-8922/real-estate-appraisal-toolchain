## 二、P1 — 应当修复

### P1-1：`_js_str()` 未复现 JS `String()` 的对象/数组语义（comment / modifications 漂移）

对抗探测（语料外形状，同一输入双端对照）：

| 输入 | Python（oracle） | JS | 判定 |
|---|---|---|---|
| `comment: {"a":1}` | `comment="{'a': 1}"` | `comment="[object Object]"` | **漂移** |
| `comment: [1,2]` | `comment="[1, 2]"` | `comment="1,2"` | **漂移** |
| `modifications: {"x":1}` | `modifications="{'x': 1}"` | `modifications="[object Object]"` | **漂移** |

**根因**：`tests/dp_action_oracle.py` 的 `_js_str()` 只覆盖 None/bool/整数值 float，其余回退 Python `str()`；
JS 侧 `String(obj)` 恒为 `"[object Object]"`、`String(arr)` 为逗号 join（元素再经 String）。
`comment`/`modifications` 的 schema 约束是 `type: string`（入口拦截），但与 Round 6 P1-1 相同的直调路径
（dp-console 无 schema 层）可到达——同一输入双端结论不同（comment 内容不同但 ok 判定相同，属"内容级"漂移）。

**修复建议**（按 D-015 裁决原则对齐生产契约）：
1. `_js_str` 补对象/数组语义：dict → `"[object Object]"`，list → `",".join(_js_str(e) for e in x)`
   （元素递归，嵌套对象再 `[object Object]`）；布尔/数值语义已对齐。
2. 语料补 `comment_obj` / `mods_obj` 两个 kind + 固化锚点（P1-3 教训：新增边界必须入库，否则下次仍测不到）。
3. 修复后重跑：N=1000 动作差分应仍 0 分歧。
