## 一、本次完成的功能

### 1.1 Schema v1.2 — 修正系数多子项支持

| 新增 | 说明 |
|------|------|
| `adjustments.locationDetails[]` | 区位修正子项（12 项，对应 Excel 行7-18），100 基准指数 |
| `adjustments.physicalDetails[]` | 实物修正子项（8 项，对应 Excel 行24-31），100 基准指数 |
| `adjustments.interestDetails[]` | 权益修正子项（5 项，对应 Excel 行19-23），100 基准指数 |
| `$defs.factorDetail` | `{required:[name,factor], additionalProperties:false}` 结构约束 |
| `$defs.calculationNode` | calculationChain 节点定义 |
| 根 schema `schemaVersion` pattern | `"^1\.2$"` |

**关键设计决策**：
- 子项用 **100 基准指数**（100=相同，>100=优，<100=劣），顶层系数保留小数倍率
- **合并口径修正为偏差加总法**：`100/(100+Σ(f-100))`，与 Excel 实际算法一致（非连乘法）。此修正由 v1.1→v1.2 测试锁定，不再依赖口头约定
- 顶层系数仍为合并值，与子项可互推（实测示例数据自洽 F1-F8 全一致）

### 1.2 Excel 公式 → JSON 计算链

| 脚本 | 职责 |
|------|------|
| `scripts/extract_calculation_chain.py` | 从 Excel 提取公式 → JSON `calculationChain`（自动推断列布局） |
| `scripts/rebuild_excel_formula.py` | Schema → Excel 公式重建，双模式 |
| `scripts/populate_excel_from_schema.py` | Schema ↔ Excel 双向数据回填与验证 |

**calculationChain 结构**（已固化在 `outputs/calculation_chain.json`）：
```json
{
  "version": "1.2",
  "nodes": [
    {"id": "comps.adjustedUnitPrice.instance1", "formula": "...", "refs": {...}, ...},
    // ... 共 8 节点
  ]
}
```

**rebuild_excel_formula.py 双模式**：
- `--mode values`：数值求值验证（7/8 PASS，`income.value` SKIP 是数据口径问题）
- `--mode cells`：单元格引用重建，与 Excel 原公式归一化后 **8/8 逐字一致**

**extract_calculation_chain.py 自动推断**（v1.2.1 更新）：
- `_detect_instance_layout()`：解析 T32/W32/Z32 公式自动识别实例列组（eval_col + idx_col）
- 动态生成 PAIR_RULES（比值对折叠）和 SUM 展开规则
- 不再依赖 `FACTOR_LAYOUT` 硬编码，支持任意列布局的 Excel 模板

**公式模板语法**：
- `{{refKey}}` — 引用 refs 中的数据值
- `SUM({{refKey}})` — Details 数组取 factor 并求和
- 数值常量直接内嵌（如权重 0.5/0.3/0.2）
- 局部中间量保留原 Excel 单元格引用（如 G23）

### 1.4 safe_eval 白名单扩展

在 P0 修复基础上扩展，支持更多 Excel 函数：

| 新增 | 说明 |
|------|------|
| `MAX` / `MIN` | 多参数取最大/最小 |
| `ABS` | 绝对值 |
| `AVERAGE` | 算术平均 |
| `POWER(x, n)` | 幂运算（`^` 的函数写法） |
| `INT(x)` | 截断取整 |
| `SQRT(x)` | 平方根 |
| `IF(cond, true, false)` | **惰性求值**——只 walk 匹配分支，未取分支不执行 |
| `AND(...)` / `OR(...)` | 逻辑与/或（Excel 函数式） |
| 比较运算符 | `= <> < <= > >=`（AST Compare 单次比较，拒绝链式） |
| 预处理 | `<>` → `!=`（Excel 语法转 Python） |

**安全不变量**（未放宽）：
- `BoolOp`（Python `and`/`or` 运算符）仍被拒绝——用 `AND()`/`OR()` 函数代替
- 属性访问/下标/推导式/lambda/名称引用仍全部拒绝
- 8 条逃逸 payload 仍全部拦截

commit `742c200` 及之前提交包含真实项目数据（含敏感信息）。公开仓库任何人均可通过 `git log -p` 读取历史。

**处置选项**（第一轮已评估）：

**建议**：如仓库仍保持公开，倾向 B；如计划转私有，倾向 C；如已确认数据均虚构无实际风险，可 A 关闭。

### 2.2 [P1] redLineChecks 语义弱（未改，设计权衡）

实测 `rule` 可填任意文本、`passed` 可全 false 仍通过 schema。这是有意放宽——红线判定依赖线下专业核验，schema 只保证"有检查记录"这一结构，不代行业务判断。validate_degraded 已强制"至少一个方法红线非空"。

**若需收紧**：
- `rule` 改为 enum（固定 7 条规范红线规则名）
- `passed=false` 时必填 `detail`（含问题描述 + 修正建议）

### 2.3 [P2] income.value SKIP 在 values 模式

示例数据采用 directCapitalization 模式，无 `growthRate` 字段，导致该节点无法求值。该节点公式适用于 fullRemainingLife/holdAndResale 模式。示例数据升级 v1.2 时选择保留 directCapitalization，未引入 growthRate。

**建议后续**：若需完全覆盖，可在示例中增加 fullRemainingLife 模式案例，或把 income.value SKIP 视为已知数据缺口文档化（HANDOFF 已有说明）。
