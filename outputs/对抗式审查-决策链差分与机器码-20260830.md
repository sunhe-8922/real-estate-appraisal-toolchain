## 二、P1 — 应当修复

### P1-1：畸形输入双端漂移 ×4（validateChain 侧；类型防御边界）

对抗探测（语料外形状，同一输入双端对照）：

| 输入 | Python | JS | 判定 |
|---|---|---|---|
| `supersedes: 42`（数值型） | `C1:key=42` | **静默** | 漂移（JS 只认 string supersedes，Python 只挡 None） |
| DP **缺 id 字段** + supersedes 指向存在节点 | `C5:key=None`（**假阳性**：`cursor == dp_id` 的 `None == None`） | 静默（C5 循环跳过非 string id） | 漂移 |
| 同上 + attempt 跳号 | `C6:key=None` | `C6:key=undefined` | 漂移（C5 假阳性 + key 渲染 None vs undefined） |
| id/supersedes 含冒号 `DP:a`（分叉） | `C4:key=DP:a` | `C4:key=DP` | 漂移（码格式 `key=` 遇 `:` 歧义，JS 正则 `[^:]*` 截断） |

**根因**：Python `_check_decision_chain` 对 `id`/`supersedes` 只做 `is None` 检查；JS 一律 `typeof === "string"` 才参与。码格式 `C<n>:key=<id>` 未约定 key 的字符约束。
**暴露面**：schema 拦截（`id` 必填 string、`supersedes` string）→ 正常工程 JSON 到不了这里；但 `dp-console.html` 直调 `validateChain()` 无 schema 层（P0-1 同款先例），畸形 DP 理论上可从编排层缺陷漏入。**定 P1 不定 P0**。
**修复建议**：① Python 对齐 JS 的 string-only 语义（`isinstance(x, str)` 参与判定，非字符串 supersedes 视同缺失或不参与）② C5 判环前先验证 `isinstance(dp_id, str)` ③ key 归一化：两端对非 string id 的 key 渲染统一（如固定 `key=<non-string>`）④ 码格式文档写明 key 约束，或 key 改用 JSON 编码。
**防复发**：把上述 4 个形状加进 `chain_shapes.py`（新 kind）+ 固化锚点，参照 Round 4 手法。
