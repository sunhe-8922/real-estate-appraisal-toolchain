## ⚠️ CRITICAL: 三条红线 + 方法优先级 (READ FIRST)

1. **FIRST: 优先选用动态分析法**（4.5.2条第1款）— 动态法对后续支出和收入做折现，不另算利息和利润
2. **NEVER 用成本法测算开发完成后价值**（4.5.7条第1款）— 这是不可逾越的红线，必须用比较法或收益法
3. **NEVER 在动态分析法中另外测算投资利息和应得利润** — 折现现金流已隐含这两项（4.5.2条第2款）
4. **估价前提必须与估价目的匹配** — 抵押→被迫转让；征收→业主自行开发（4.5.3条）

**Why this matters:** 假设开发法是参数最多、最敏感的方法——估价前提、折现率、开发周期的微小变化会导致结果大幅波动。不规范使用会给出完全失真的结果。

## Overview

假设开发法的核心公式：

```
动态分析法：开发价值 = 开发完成后价值折现 - 后续必要支出折现
静态分析法：开发价值 = 开发完成后价值 - 后续必要支出 - 投资利息 - 应得利润
```

适用于有开发或再开发潜力的房地产，是土地估价和在建工程估价的必备方法。

## 一、8 步工作流

### Step 1: 选择具体估价方法（4.5.2条）

```
动态分析法 vs 静态分析法
├─ 优先：动态分析法
│   ├─ 对后续支出和开发完成后价值进行折现
│   └─ 不另外测算投资利息和应得利润
└─ 静态分析法（仅在简单项目或参数不足时使用）
    ├─ 另外测算投资利息
    └─ 另外测算应得利润
```

### Step 2: 选择估价前提（4.5.3条）

| 估价前提 | 含义 | 适用估价目的 |
|---------|------|-------------|
| **业主自行开发** | 假设业主自己继续开发 | 征收估价（5.3.3-4）、投资分析 |
| **自愿转让开发** | 假设自愿转让给他人开发 | 出让估价（5.10.5）、一般市场价值 |
| **被迫转让开发** | 假设被迫转让给他人开发 | 抵押估价（5.1.4）、司法拍卖（5.4.2-4） |

**估价前提影响参数取值：**
- 自愿/被迫转让开发 → 后续支出含估价对象取得税费
- 被迫转让开发 → 开发完成后价值取保守值、折现率取较高值

### Step 3: 选择最佳开发经营方式（4.5.4条）

基于以下信息判断最优开发方案：
- 估价对象状况（地块条件、容积率限制、建设现状）
- 所在地房地产市场状况（产品类型热度、价格水平）
- 规划条件（用途、容积率、建筑密度、限高）

**输出**：明确开发完成后的房地产状况（用途、规模、档次）及其经营方式（出售/出租/自持）。

### Step 4: 测算后续开发经营期（4.5.5条）

将开发经营期分为三个阶段：

| 阶段 | 定义 | 测算依据 |
|------|------|---------|
| **前期** | 从价值时点到开工建设 | 规划审批、设计招标周期 |
| **建造期** | 从开工到竣工验收 | 类似项目施工工期 |
| **销售期** | 从预售/竣工到销售完毕 | 市场去化速度、类似项目 |

**测算依据**：估价对象状况、未来开发完成后的房地产状况及经营方式、类似项目一般期限、估价前提。

### Step 5: 测算后续开发的必要支出（4.5.6条）

#### 动态分析法构成

| 构成项 | 说明 |
|--------|------|
| 建设成本 | 后续建造的建安工程费等 |
| 管理费用 | 开发管理支出 |
| 销售费用 | 营销推广费用 |
| 销售税费 | 销售环节税费 |
| 估价对象取得税费 | 仅自愿/被迫转让开发前提（契税等） |

**注意**：动态分析法中各支出为**预计未来发生时的金额**（折现前）。

#### 静态分析法构成（另加）

| 构成项 | 说明 |
|--------|------|
| 投资利息 | 各项支出在后续开发期内的资金成本 |
| 应得利润 | 开发类似项目应得的正常利润 |

### Step 6: 测算开发完成后的价值（4.5.7-4.5.9条）

#### ⚠️ 红线：不得用成本法！

必须用以下方法：

| 方法 | 适用条件 | 测算内容 |
|------|---------|---------|
| **比较法** | 有类似开发完成后的房地产交易 | 先测单价 × 面积/体积 |
| **收益法** | 开发完成后用于出租或经营 | 预测未来收益折现 |

**分用途测算**：开发完成后有不同用途/档次时，分别测算各部分的单价再相加。

#### 动态 vs 静态的时间口径

| 方法 | 价值时点 |
|------|---------|
| 动态分析法 | 未来开发完成时的价值（可考虑预售/延迟销售） |
| 静态分析法 | 假设未来开发完成后的房地产在价值时点的价值 |

**动态法中价值预测**：根据类似房地产未来市场价格变动趋势预测（4.5.8条第2款）。

### Step 7: 确定折现率或应得利润（4.5.10-4.5.12条）

| 参数 | 方法 | 确定方式 |
|------|------|---------|
| **折现率**（动态） | 类似房地产开发项目要求的收益率 | 市场调研、同类项目投资回报 |
| **投资利息**（静态） | 利率 × 计息基数 × 计息期 | 估价对象价值 + 建设成本 + 管理费用 + 销售费用（+ 取得税费） |
| **应得利润**（静态） | 计算基数 × 开发利润率 | 类似项目开发利润率 |

**静态法计息基数（4.5.11条）：**
```
计息基数 = 估价对象价值 + 建设成本 + 管理费用 + 销售费用
若为转让开发前提，再加：估价对象取得税费
各基数计息期分别自发生时起至建设期结束时止
```

### Step 8: 计算开发价值（4.5.13条）

```
动态分析法：
开发价值 = Σ 开发完成后价值ₜ/(1+r)ᵗ - Σ 后续支出ₜ/(1+r)ᵗ

静态分析法：
开发价值 = 开发完成后价值 - 后续必要支出 - 投资利息 - 应得利润
```

**试算逻辑**：静态法中估价对象价值出现在等式两边（既是结果又是计息基数的一部分），需要设未知数列方程或用试算法求解。

## 二、三条红线详解

### 红线 1：开发完成后价值必须用比较法或收益法

4.5.7条第1款明确规定"不应采用成本法测算"。这是为了保证开发完成后价值反映市场水平而非成本堆砌。

### 红线 2：动态分析法不另算利息和利润

折现现金流本身隐含了时间价值和风险回报，重复计算会低估开发价值。

### 红线 3：估价前提必须与目的匹配

| 估价目的 | 应选前提 | 出处 |
|---------|---------|------|
| 抵押估价（待开发房地产） | 被迫转让开发 | 5.1.4 |
| 征收估价（正常开发项目） | 业主自行开发 | 5.3.3-4 |
| 征收估价（非征收原因停建） | 自愿转让开发 | 5.3.3-5 |
| 出让估价（出让人） | 自愿转让开发 | 5.10.5 |
| 司法拍卖估价 | 被迫转让开发 | 5.4.2-4 |

## 六、结构化输出（JSON）

完成测算后，除 Excel/表格输出外，**必须同时输出结构化 JSON 片段**，供 `appraisal-report` 技能读取组装报告。

完整 Schema 定义：`schema/appraisal-result.schema.json`
完整示例：`schema/example-武汉洪山住宅.json`（`methods.hypotheticalDev` 部分，示例中为 null — 该案例未采用假设开发法）

本方法输出的 JSON 结构（假设采用假设开发法时）：

```json
{
  "hypotheticalDev": {
    "applicable": true,
    "analysisMethod": "dynamic",
    "premise": "ownerInitiated",
    "developmentValue": 5000000,
    "subsequentCosts": {
      "construction": 1000000,
      "management": 50000,
      "investmentInterest": 0,
      "salesTax": 150000,
      "developerProfit": 0
    },
    "discountRate": 0.08,
    "developmentPeriod": 1.5,
    "finalValue": { "total": 3800000, "unit": 29572 },
    "weight": 0.5,
    "weightRationale": "待开发土地，假设开发法为主要方法",
    "redLineChecks": [
      { "rule": "完成后价值禁成本法", "threshold": "4.5.7条", "actualValue": "用比较法测算", "passed": true },
      { "rule": "动态法不另算利息利润", "threshold": "4.5.6条", "actualValue": "利息利润=0", "passed": true },
      { "rule": "前提匹配估价目的", "threshold": "4.5.2条", "actualValue": "业主自行开发匹配抵押目的", "passed": true }
    ]
  }
}
```

**输出要求**：
- `analysisMethod` 必须明确（dynamic / static）
- `premise` 必须匹配估价目的（抵押→ownerInitiated / 拍卖→forcedTransfer）
- `subsequentCosts.investmentInterest` 和 `developerProfit` 在动态法中必须为 0
- 若假设开发法不适用，设 `applicable: false` 并填 `notApplicableReason`

**输出前自检**（使用验证脚本）：
```bash
python scripts/validate_appraisal_json.py --fragment hypotheticalDev <你的JSON文件>
```
验证通过后再传给 `appraisal-report` 技能。常见错误：动态法下 `investmentInterest`/`developerProfit` 不为 0、`premise` 值不在枚举内、缺少 `discountRate`。

## 七、持续改进

After completing 假设开发法测算, ask:

1. 开发经营期各阶段是否可参照更相似的项目？
2. 开发完成后价值预测是否充分考虑了市场趋势？
3. 折现率/利润率是否需要更新（市场利率变化）？
4. 是否有更好的开发方案（用途组合、规模优化）？
5. 各参数是否需要敏感性分析（折现率±1%、工期±6月的价值变化）？
