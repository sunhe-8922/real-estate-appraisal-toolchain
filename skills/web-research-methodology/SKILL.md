# 联网信息收集方法论

研究报告的价值完全取决于信息的丰富度和准确性。必须联网搜索，不能仅靠已有知识。信息收集阶段宁可多搜，不要因为信息不够导致后面的分析浮于表面。

## 一、并行搜索策略

使用子 Agent 并行搜索提高效率。根据研究对象复杂度选择 2 或 3 个子 Agent 分工：

### 子 Agent 1 — 纵向信息

研究对象的历史纵深与演进脉络。

- 起源：何时、何地、由谁创建，解决什么问题
- 创始人背景：学术/行业经历、之前的项目、技术哲学
- 发展历程：关键里程碑、版本迭代时间线
- 关键事件：重大发布、战略转向、危机事件、争议
- 融资与商业化：融资轮次、估值变化、商业模式演进

### 子 Agent 2 — 横向信息

研究对象的竞争格局与市场定位。

- 竞品识别：同赛道玩家有哪些，直接竞品和间接竞品
- 各竞品特点：技术路线差异、功能对比、目标用户差异
- 用户口碑：开发者/用户评价、社区活跃度、迁移倾向
- 行业对比评测：第三方评测、Benchmark 结果
- 市场份额：如有公开数据则收集，无则标注"无可靠数据"

### 子 Agent 3 — 补充信息（复杂对象才启用）

- 创始人深度背景：学术发表、演讲观点、社交网络画像
- 行业环境变化：政策法规、技术趋势、资本热度
- 用户社区讨论：GitHub Issues、Reddit、Twitter/X、知乎、HackerNews

## 二、子 Agent 联网工具使用指南

以下指引必须直接写入每个子 Agent 的 prompt 中：

**你需要联网获取信息。使用以下工具：**

- **WebSearch**：用于搜索发现信息来源，获取摘要和关键词结果
- **WebFetch**：当已知具体 URL 时，用于从页面定向提取内容

**搜索策略**：
1. 先用 WebSearch 发现信息来源和线索
2. 找到具体 URL 后用 WebFetch 深入提取
3. 多次搜索、多个关键词组合，不要只搜一次就放弃
4. 一手来源优于二手来源：官方博客 > 权威媒体原创报道 > 转载/聚合

**学术类研究对象必查 arXiv**：
如果研究对象涉及学术概念、算法、AI 模型、技术范式等，必须通过 arXiv API 获取相关论文。
- 调用方式：使用 WebFetch 访问 `https://export.arxiv.org/api/query?search_query=all:关键词1+AND+all:关键词2&max_results=10`
- 返回 XML 格式，包含标题、作者、摘要、发布日期、PDF 链接
- 可按需调整关键词组合和结果数量
- 找到关键论文后，用 WebFetch 读取论文页面（https://arxiv.org/abs/论文ID）获取更多细节

**prompt 写法要点**：描述目标（"获取""调研""了解"），不要用暗示具体手段的动词（"搜索""爬取"），让子 Agent 自主判断最佳获取方式。

## 三、信息来源优先级

一手来源优于二手来源。多个媒体引用同一个错误会造成循环印证假象。

| 信息类型 | 一手来源 | 信源等级 |
|---------|---------|---------|
| 产品更新/技术决策 | 官方博客、GitHub Release Notes、创始人推文 | T0 |
| 融资/商业数据 | 公司官方公告、SEC/工商文件 | T0 |
| 用户口碑 | GitHub Issues、Reddit 讨论、Twitter/X、知乎帖子 | T1（交叉验证后采信） |
| 行业分析 | 权威媒体原创报道（非转载） | T1 |
| 学术/技术原理 | arXiv 论文、Google Scholar、学术会议论文集 | T0 |
| 自媒体/百科/AI 生成 | — | T2（仅作线索，不可作论据） |

**红线**：核心论点只有 T2 级信源支撑时，必须标注"缺乏权威信源，仅供参考"。

## 四、信息充分性自检

搜索完成后，逐维度检查：

### 纵向充分性
- [ ] 能讲出一个完整的故事吗？从起源到现状有没有明显的信息断层？
- [ ] 关键转折点有可靠来源吗？还是只是"据说"？

### 横向充分性
- [ ] 竞品列表完整吗？有没有遗漏主要玩家？
- [ ] 每个竞品的信息够做对比吗？（至少覆盖：定位、功能、用户群、技术路线）

### 来源可靠性
- [ ] 关键事实有可靠来源支撑吗？
- [ ] 有没有只靠单一来源就下判断的？
- [ ] T0/T1 信源占比是否超过 60%？

**信息不够就再补搜。不要凑合。**

## 五、子 Agent 启动模板

使用 Agent 工具启动子 Agent 时，参考以下模板构建 prompt：

### 纵向子 Agent prompt 模板

你是一个研究助手，任务是获取 [研究对象] 的纵向信息：起源、创始人背景、发展历程、关键事件、版本迭代、融资、战略转向、危机。

将上述"子 Agent 联网工具使用指南"的内容粘贴到这里。

要求：
- 每条信息标注来源 URL 和信源等级（T0/T1/T2）
- 信息断层处明确标注"此处信息不足，需补充"
- 输出结构：时间线表格 + 关键事件详述 + 信息缺口列表

### 横向子 Agent prompt 模板

你是一个研究助手，任务是获取 [研究对象] 的横向信息：竞品识别、各竞品特点和用户口碑、行业对比评测、市场份额。

将上述"子 Agent 联网工具使用指南"的内容粘贴到这里。

要求：
- 竞品列表至少覆盖 3 个直接竞品
- 每个竞品收集：定位、核心功能、技术路线、用户评价、市场份额（如有）
- 输出结构：竞品对比表 + 口碑摘要 + 市场格局分析

### 补充子 Agent prompt 模板（复杂对象）

你是一个研究助手，任务是获取 [研究对象] 的补充信息：创始人深度背景、行业环境变化、用户社区讨论（GitHub Issues、Reddit、Twitter/X、知乎等）。

将上述"子 Agent 联网工具使用指南"的内容粘贴到这里。

要求：
- 社区讨论收集正反两面声音，不要只选一边
- 行业环境聚焦影响研究对象走向的外部因素
- 输出结构：创始人画像 + 行业环境分析 + 社区舆论摘要

## 六、输出整合

三个子 Agent 返回后：

1. **去重合并**：相同事实只保留信源等级最高的一条
2. **交叉验证**：同一事实多个来源一致 → 可信；矛盾 → 标注分歧
3. **缺口标注**：未获取的信息明确列为"待补充"
4. **信源统计**：报告末尾附信源分布（T0/T1/T2 占比）
